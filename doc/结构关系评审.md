# 本体结构关系评审

评审范围：`extract/slots.py` 的 10 个实体间结构关系，以及 `doc/本体与关系设计方案.md` 第 3.3 节的定义。
数据基础：`data/extract/kgv9_huanqiu_mil_2026-01.jsonl`（200 篇 / 745 事件 / 1851 论元）。

---

## 一、结论先说

**「辖属」与「隶属」不冗余，二者语义清晰可分。真正的问题在别处：这条链在你最需要它的地方（国别归属）是断的。**

实测 196 个机构实体，只有 18 个（9.2%）有辖属边。而最高频的机构全都没有：

```
以色列国防军    28 篇   ✗ 无国家
美军            12 篇   ✗ 无国家
黎巴嫩真主党    10 篇   ✗ 无国家
俄罗斯国防部     9 篇   ✗ 无国家
伊朗伊斯兰革命卫队 7 篇  ✗ 无国家
胡塞武装         6 篇   ✗ 无国家
```

你想用「辖属」解决的正是这个场景：文本里只有「美军驻地」，没有「美国」，但可视化时需要把它挂到美国下面。现在这条边拿不到。

> **已修复。**改提示词后重跑 200 篇，辖属覆盖率从 9.2% 提升到 80% 以上。详见第九节。

## 二、辖属与隶属是否冗余：不冗余

### 语义上确实不同

| 关系 | 含义 | 实例 |
| --- | --- | --- |
| 隶属 | 上级机关（组织层级） | 以色列空军 → 以色列国防军 |
| 辖属 | 国别归属（主权归属） | 美国空军 → 美国 |

「以色列空军」隶属「以色列国防军」，但它的国别归属是「以色列」——这是两个不同的断言，不能合并。而且隶属链可以很长：

```
海军情报局 → 伊朗伊斯兰革命卫队海军 → 伊朗伊斯兰革命卫队 → （→ 伊朗？）
```

层级关系天然是链，国别归属天然是单跳。合并会丢失层级结构。

### 数据上也没有混淆

实测两者没有一条重复：

```
隶属 9 条：全部 机构→机构
辖属 18 条：全部 机构→国家
```

端点类型完全分离，没有把「美国国防部→美国」写成隶属之类的错误。

### 但传递闭包补不上国别——这是关键发现

我试过「沿隶属链上溯找辖属」，23 个机构里 7 个失败：

```
✗ 美国南方司令部   隶属→美国国防部        （美国国防部无辖属边）
✗ 以色列空军       隶属→以色列国防军      （以色列国防军无辖属边）
✗ 哈马斯情报部门   隶属→哈马斯            （哈马斯无辖属边）
✗ 海军情报局       隶属→伊朗伊斯兰革命卫队海军 → …
✗ 伊朗伊斯兰革命卫队海军 → 伊朗伊斯兰革命卫队 → …
✗ 国防省           隶属→朝鲜劳动党
✗ 真主党"巴德尔"地区部队 隶属→黎巴嫩真主党
```

**失败的原因不是链条逻辑错，而是链条末端那个机构（以色列国防军、美国国防部、哈马斯）自己没有辖属边。** 换句话说，缺失发生在源头，不在传递。

## 三、真正的问题：国别归属这条链有三处断点

### 断点 1：提示词把「辖属」写成「原文必须明说」

```525:528:extract/kg_extract.py
结构关系（实体与实体之间，只收稳定关系，不随单次事件变化）：
隶属 机构→机构（上级机关）
辖属 机构→机构（国别归属，终点是国家）
驻地 机构→地点（常驻位置）
```

它被归入「只收稳定关系」，紧接着一段是：

```541:544:extract/kg_extract.py
五条结构关系的边界：
任职只看原文是否写明职务与机构的对应关系，「曾在该机构工作」不算任职。
```

模型读到的整体语义是「**原文没写就别建**」。

但我实测了一个反证：**88 次机构提及中，84 次正文里就有对应国家名**（95%）。

```python
targets={"以色列国防军":"以色列","美军":"美国","俄罗斯国防部":"俄罗斯",...}
# 正文中包含目标国家名：84 次；不包含：4 次
```

也就是说，绝大部分国别**原文是可证的**，不是需要推理的。模型没建边，是提示词的倾向性造成的，不是能力问题。

### 断点 2：辖属的端点定义写错了

```303:303:extract/slots.py
    add("辖属", {"机构", "国家"}, {"国家"})
```

问题在两处：

1. 注释写「机构→机构（终点是国家）」，但 `add` 的起点给了 `{机构, 国家}` 两个类型。国家辖属于国家是无意义的（「伊朗辖属伊朗」），这个口子没必要开。
2. 终点严格要求类型是「国家」。但模型常写「美军→美国军方」「以军→以军总部」这类机构名结尾，会被 `DOMAIN` 校验判为类型不匹配丢弃。

### 断点 3：「位于」链到不了国家

我原以为「地点 → 位于 → 国家」能兜底，实测不行：

```
卡杜格利     → 南科尔多凡州 [地点]
伊斯法罕     → 伊斯法罕省   [地点]
纳坦兹核设施 → 伊斯法罕省   [地点]
温赖特基地   → 阿尔伯塔省   [地点]
```

6 条「位于」的终点**全是省级/市级地点，没有一个是国家**。所以「省 → 国家」这一跳根本不存在，链条断在最后一步。

## 四、另外四个关系的问题

### 4.1 有 4 个关系近乎空转

```
任职   29 条   ✓ 可用
辖属   18 条   ✓ 可用
隶属    9 条   ✓ 勉强可用
敌对    8 条   ✓ 勉强可用
位于    6 条   △
驻地    1 条   ✗
部署方  1 条   ✗
搭载    1 条   ✗
会晤    1 条   ✗
去向    1 条   ✗
```

后 5 个各只有 1 条。设计上它们没错，但在军事快讯语料里几乎不出现——快讯讲事件，不讲「某舰搭载某导弹」这种静态配置。若 RE 任务是训练目标，这 5 个关系需要专门的语料，或干脆从本体里去掉。

### 4.2 「敌对」的端点定义与文档不符

文档写「机构/国家 → 机构/国家」，但实测 8 条全是 `机构→机构`。这不一定是错（国家之间的敌对通常被表述成事件而非稳定关系），但**定义与实现不一致**，应择一。

### 4.3 「驻地」与「部署方」的语义边界模糊

```
驻地   中国驻符拉迪沃斯托克总领事馆 → 符拉迪沃斯托克   （常驻）
部署方 波音C-40"快船"运输机 → 美国国防部              （谁部署的）
```

「中国驻符拉迪沃斯托克总领事馆」这个例子说明：**机构名本身已经编码了地点和国别**（中国驻…），但还要单独建驻地边。这类「自解释名称」是否要额外建边，需要明确规则，否则同一信息在节点名和边里各存一份。

### 4.4 「位于」与「辖属」在语义上有交叠风险

「纳坦兹核设施 → 伊斯法罕省」是位于（地理包含），而如果写「纳坦兹核设施 → 伊朗」，就是辖属（国别归属）。一个设施可能同时需要两条。当前定义允许这样，但**没有说明何时该建哪条**，模型会二选一。

## 五、针对你的用途（可视化国别归属）的建议

核心判断：**你要的是「机构的国家」这个属性，而它现在被当成「文本关系」在抽，这是错配。**

建议分两件事做，不要再混在一起：

### 第一件事：把「可证的国别」抽全（改提示词，收益最大）

既然 84/88 的国别在正文里就有，那么只需要改提示词的倾向：

- 明确「机构名含国名（伊朗国防部、俄罗斯国防部）→ 必须建辖属」
- 明确「正文出现该机构所属国家 → 必须建辖属」，不再受「只收稳定关系」的暗示压制
- 去掉辖属起点的「国家」类型（只留机构）
- 允许终点是「国家」，不允许是机构；模型写成机构名时，用该机构已有的辖属反查

预期能把 9.2% 的覆盖率提到 50% 以上（高频机构基本都能覆盖）。

### 第二件事：推断补全，但必须标注来源

剩下的真·无文本依据的（如「美军驻地」全文无「美国」），需要常识推断。我实测了模型能力，18 个机构里 13 个能准确给国家，跨国组织也正确留空：

```
以色列国防军 → 以色列    ✓
美军 → 美国              ✓
胡塞武装 → 也门          ✓
北约 → （空，跨国联盟）   ✓
伊斯兰国 → （空，跨国）   ✓
库尔德武装 → （空，跨多国）✓
国防部 → （空，名称不完整）✓
```

但**推断结果必须和可证结果分开存**：

```json
{"head": "美军", "relation": "辖属", "tail": "美国",
 "source": "inferred", "confidence": "high"}
{"head": "美国空军", "relation": "辖属", "tail": "美国",
 "source": "text", "evidence": "美国空军出动F-35…"}
```

理由：图谱里这两类边的可信度不同。可视化时推断边用虚线或淡色，用户一眼能看出「这是推的」。如果不区分，一旦推断错了（比如把「国防部」错认成某国），整个图谱的可信度都会被质疑。

### 第三件事：全局一致性

同一机构在 200 篇里应只有一个国别。当前逐篇独立抽取，「以色列国防军」在 A 篇有边、B 篇没有。需要在后处理阶段做一次全局归并：以「原文可证」优先，冲突时取证据最长的；推断结果只在无文本证据时使用。

## 七、一句话总结

**辖属和隶属不冗余，但「靠它们拿到国别归属」这件事在当前实现下是失败的——不是因为关系设计错，而是因为提示词把「可证的国别」当成了「需要谨慎判断的稳定关系」，导致 95% 本可以直接抽出的边被漏掉。**

先修提示词（P0），再谈推断补全（P1）。推断只是补最后 5% 的缺口，不该是主力手段。

## 九、实施结果

### 改了什么

1. **提示词改写辖属判据**：从「只收稳定关系」的被动语气，改为三条明确判定规则——机构名含国名、正文提到所属国家、名称含国别标志，满足任一即建边。同时列出跨国机构与双边共管机构的排除清单。
2. **端点定义修正**：`辖属` 起点从 `{机构, 国家}` 收为 `{机构}`，杜绝「伊朗辖属伊朗」这类无意义边。
3. **后处理修正层**：新增 `extract/country_infer.py`，剔除跨国机构被强加的归属、双边共管机构被归到多国的边，并给每条辖属边打 `source` 标记（`text` / `marker` / `inferred`）。

### 效果

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 辖属边 | 18 | **450**（修正后 413） |
| 辖属覆盖率 | 5.6% | **90.1%** |
| 辖属去重（机构-国家对） | 18 | **250** |
| RE 卷篇数 | 29 | **120** |
| RE 卷三元组 | 75 | **414** |

RE 卷的扩充是意外收获：辖属边大量出现后，含结构关系的篇目从 29 篇涨到 120 篇。

### 质量检查

- 同一机构归到多个国家：**0**（后处理已消除）
- 「泰柬边界委员会」这类双边机构：已正确排除，不再归到任一国
- Top 10 高频机构全部正确：

```
以色列国防军 → 以色列      美国武装力量 → 美国
伊朗伊斯兰革命卫队 → 伊朗   伊朗武装部队 → 伊朗
美国国防部 → 美国          俄罗斯国防部 → 俄罗斯
以色列空军 → 以色列        乌克兰武装部队 → 乌克兰
白宫 → 美国               俄罗斯武装力量 → 俄罗斯
```

### 遗留

- 仍有个别误标，如「联合国 → 美国」（模型按篇内语境归错），后处理能拦掉一部分，但 `TRANSNATIONAL` 名单需要持续补充。
- 「国防部」单写时归到中国的 5 条，是模型按上下文推断（中国国防部发布会语境），实际可接受，但若要求严格应改为不建边。
- 抽取阶段尚未使用 `source=inferred`——当前 413 条全部是文本或名称可证。真正的常识推断（如「美军驻地」全文无「美国」）已由规则 1 覆盖，不需要额外调模型。
