# 事件类型体系重构方案

> 现状问题：16 类平铺，抽象层次混杂（「空袭」与「打击」并列、「声明」占 49%），
> 且 `setting` 与 `event_type` 有 7 个词重复，10.1% 的事件出现 `部署 × 部署` 这类无意义组合。
>
> 本方案参考 CAMEO 的层级编码思想与 CMNEE 的分布均衡度，改为两层结构。

## 一、参照对象的实测数据

### CAMEO 可借鉴之处

1. **数字编码天然分层**：20 个一级类，每位下 3–6 个细分。判定时先看一级，再决定是否需要细分。
2. **按「行为性质」而非「动作形式」分级**：「空袭」在 CAMEO 里是 `19 FIGHT → 195 Employ aerial weapons`，不是与 FIGHT 并列。
3. **把表态正当化**：`01 MAKE PUBLIC STATEMENT`、`02 APPEAL`、`03 EXPRESS INTENT TO COOPERATE` 都是正式类别。国际事件中表态本身即行为。

### CMNEE 实测分布（12000 篇）

## 二、新体系设计

### 两层结构

```
event_type  一级，行为性质，5 类
subtype     二级，具体形态，按一级分化
```

### 一级：event_type

| 一级 | 定义 | 判据 |
| --- | --- | --- |
| 对抗 | 双方或多方发生武力冲突、控制争夺、强制行为 | 有明确的敌对方，或单方施加武力 |
| 部署 | 兵力的移动、集结、演练、撤收，无直接交火 | 主体是己方兵力，动作是调动类 |
| 合作 | 达成协议、磋商、会晤、支援 | 多方参与，指向共识或互助 |
| 表态 | 言语行为，无实际动作 | 只有说，没有做 |
| 其他 | 事故、立法、人事、调查等 | 不属上述四类 |

### 二级：subtype

**对抗（5 类）**

| subtype | 判据 | 现有映射 |
| --- | --- | --- |
| 打击 | 地面、海上或导弹攻击 | 打击 2,529 |
| 空袭 | 飞机投弹或扫射 | 空袭 689 |
| 拦截 | 击落、拦截来袭目标 | 拦截 504 |
| 发射 | 发射弹药或飞行器（不含命中） | 发射 273 |
| 控制 | 占领、接管、封锁、拘押 | 控制 262 + 逮捕 16 |

**部署（3 类）**

| subtype | 判据 | 现有映射 |
| --- | --- | --- |
| 部署 | 增兵、调动、集结、战备 | 部署 579 |
| 演习 | 军事演习、训练、试射 | 演习 246 |
| 撤离 | 撤军、撤退、返航 | 撤离 114 |

**合作（5 类）**

| subtype | 判据 | 现有映射 |
| --- | --- | --- |
| 签署 | 签订协议、条约、加入组织 | 签署 283 |
| 谈判 | 谈判、磋商、达成共识 | 谈判 225 |
| 会议 | 正式会议、峰会、会晤 | 会议 297 |
| 访问 | 出访、视察、接待来访 | 访问 182 |
| 援助 | 提供物资、装备、资金、人道支援 | 援助 48 |

**表态（6 类）**

| subtype | 判据 | 现有映射 |
| --- | --- | --- |
| 声明 | 一般性陈述、通告、发布信息 | 声明（部分） |
| 呼吁 | 要求、敦促、倡议 | 声明（部分） |
| 警告 | 警告、威胁、划红线 | 声明（部分） |
| 否认 | 否认、驳斥、拒绝承认 | 声明（部分） |
| 承认 | 承认、证实、确认 | 声明（部分） |
| 谴责 | 谴责、批评、抗议 | 声明（部分） |

**其他（不分二级）**

事故、伤亡统计、立法通过、人事任免、刑事调查等。

## 三、现有数据的映射

一级全部可机械映射，无遗漏：

| 一级 | 现有类 | 数量 |
| --- | --- | ---: |
| 对抗 | 打击、空袭、拦截、发射、控制、逮捕 | 4,273 |
| 部署 | 部署、演习、撤离 | 939 |
| 合作 | 签署、谈判、会议、访问、援助 | 1,035 |
| 表态 | 声明 | 6,228 |
| 其他 | 其他 | 241 |

二级映射除「表态」需重判外，其余均为一对一。

**表态的二级需要重判**：现有 6,228 条「声明」要分到呼吁/警告/否认/承认/谴责/声明六类。实测只有 23% 带 `stance` 属性（中立 512、谴责 168、警告 142、否认 137、支持 125、承认 101、反对 100、要求 69、呼吁 58），其余需重新判定。

## 四、删除 setting

现有 `setting` 的三个问题：

1. 与 `event_type` 有 7 个词重复（演习、访问、会议、谈判、签署、部署、其他），产生 1,288 条无意义组合。
2. `setting=其他` 占 31.8%，无信息量。
3. 语义模糊：`声明 × 战斗` 1,336 条，「在战斗中发表声明」缺少实际区分价值。

删除后，`kind`（发生/表态/计划）保留，它与 `event_type` 正交，是有效维度。

| 项目 | 改动 |

## 六、遗留决策

1. **subtype 的命名**：`setting` 改名后，代码字段用 `subtype` 还是 `action`？
2. **表态细分是否值得**：需重判 6,228 条，成本约 1 小时（大模型批量判定）。若不重判，表态不分二级，则一级 5 类、二级仅对抗/部署/合作三类有值。
3. **是否保留 kind**：`kind` 与「表态」一级类有重叠——表态类事件的 `kind` 必然是 `表态`。可考虑合并：表态类不设 `kind`，或 `kind` 只用于区分发生/计划。
