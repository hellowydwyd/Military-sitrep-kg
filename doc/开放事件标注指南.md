# 开放事件标注指南 v1.1

面向人工审查 LLM 预标（P1）。对照方案 `doc/事件图谱完整方案.md` v1.1。

**本页只标 Report（这篇报道主张了什么），不标世界 Event，不标 STATE，不对齐别名。**  
`kind` 是话语功能，不是袭击/演习等事件类型。trigger 开放，槽位固定。

合并、驻扎区间、日历日、as_of 由写图程序做；金标种子见 `data/eval/event_merge_seed.json`。

## 记录

每个新闻块输出 `events` 数组。不要标独立三元组，不要把时间换成 YYYY-MM-DD。

| 字段 | 要求 |
|------|------|
| trigger | 原文连续子串 |
| kind | 发生 / 表态 / 计划 |
| raw_time | 句中时间短语原样；无则 `""` |
| evidence | 含 trigger 的原句 |
| arguments.role | 仅 主体 / 对象 / 地点 / 装备 |
| arguments.text | 原文连续子串 |

金标补 `offset`。没有的槽不写，不罚。伤亡数字、互斥目标类型**不要新开角色**，留在 `evidence` 里即可（补丁 B）。

## kind

- **发生**：打击、发现、部署、发射、逮捕、相撞；仍驻扎、抵达、离开也算发生。
- **表态**：称、表示、谴责、警告、否认。警告里说「将打击」仍是表态。
- **计划**：主谓语是将、拟、计划、准备。

「据通报称……实施了打击」只留打击（发生），不另标「称」。

单方指控（仅一方说「已部署 / 已控制」，对方否认）→ **表态**，不要标成发生（补丁 C）。标注员不写 `claim_only`；写图会降级。

## 一句一事（补丁 A）

同句同主体只留一条。

- **要拆**：原文用「随后 / 之后 / 接着 / 然后」连接的两个动作 → 两条，`raw_time` 分别留线索词（发现 + 随后打击）。
- **要拆**：两处明确目标（纳季兰机场 / 阿美石油）→ 两条发生，对象各写一处。
- **不拆**：无线索的过程句（响起爆炸、短暂断电、导弹正在飞来）→ 删碎条，或并进主打击的 `evidence`，不另建一条。
- **不拆**：「称 / 进入 / 构成威胁 / 打击」四段话只留主动作。

不要拆成清单碎条。当日「几次袭击」按主打击计，不按爆炸声计。

## fact 等价（评测用）

同一 fact：「袭击」与「发动袭击」。不同 fact：「发现」与「随后发动打击」；「机场」与「炼油厂」。

## 代词

优先改成句中的名词性子串。对不上才允许「该建筑」。禁止「他 / 其 / 该部队」当唯一实体。

## 时间

只抄原文。日历日由写图处理。6 月 26 日的背景协议仍标为发生，由写图标 background。

「开始返航 / 将撤出」按原文 kind 标（发生或计划），**不要**在备注里改成「已离开」（补丁 C）。是否关闭驻扎由写图判断。

## 不要标

- 世界事件是否合并、谁和谁同一 Event
- STATE / 驻扎区间 / as_of
- 实体 canonical、结盟、敌对、导致
- YYYY-MM-DD 日历日

## 审查动作

改 / 删（幻觉、重复碎条、过程句）/ 增（漏抽、第二处目标、「随后」后件）。  
记录：多抽、漏抽、kind 错、时间错、角色错、误拆过程句、漏拆随后/两处。
