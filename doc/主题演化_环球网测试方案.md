# 新闻主题演化：可验证技术方案（环球网军事测试）

> 输入只假设带时间戳的新闻文档（标题 + 正文 + 见报日），按日追加。  
> 测试语料：本仓库 `data/raw/huanqiu_mil/*.jsonl`（环球网军事公开文字稿，不是纸媒版面）。  
> 规模：2556 篇，2026-03-29～2026-10-02，有稿日 187 天，日篇数中位 13，正文中位 262 字。

本文把「指定时间窗下的核心议题、衍生议题、迁移路径、生命周期」写成可计算对象，并给出在该语料上**先冻参数、再评测**的协议。结构计算不使用 LLM。

## 1. 问题的数学对象

### 1.1 文档流

\[
\mathcal{D} = \{d_i\}_{i=1}^{N},\quad
d_i = (\mathrm{id}_i,\ \tau_i,\ s_i)
\]

- \(\tau_i \in \mathbb{Z}\)：见报日（`publish_time` 的日历日，+08:00）。本测试**不解析文中发生日**。
- \(s_i\)：标题与正文的拼接。实现上标题重复一次再拼接正文，以补偿短讯（中位 262 字）。
- 日更：第 \(t\) 日到达集合 \(\mathcal{D}_t = \{d:\tau(d)=t\}\)，历史 \(\mathcal{D}_{\le t}\) 只增不改。

本测试回答的是**报道线随见报日的演化**，不是战场发生日的演化。二者不等价；见报日可复现，发生日需要另套抽取，不进入本方案。

### 1.2 文本表示

固定编码器 \(\phi:\text{字符串}\to\mathbb{R}^{m}\)（见 §3，本地向量，确定性）。单位化：

\[
\hat\phi(d) = \frac{\phi(s(d))}{\|\phi(s(d))\|_2}
\]

两篇稿的相似度 \(\mathrm{sim}(d,d') = \hat\phi(d)^{\top}\hat\phi(d')\)。

### 1.3 议题（开集）

议题是一条报道线，不是栏目，不是固定 \(K\) 个词分布。第 \(t\) 日结束时的议题库：

\[
\mathcal{K}_t = \{1,2,\ldots,K_t\}
\]

\(K_t\) 随数据增长，无上限。每条线 \(k\) 有：

| 符号 | 含义 |
|------|------|
| \(C_k \subseteq \mathcal{D}_{\le t}\) | 成员文档，只增 |
| \(\mu_k\) | 中心：成员向量的归一化均值（可对近期稿做指数加权） |
| \(t_k^{0},\ t_k^{\ell}\) | 首篇日、末篇日 |
| \(p_k \in \{0\}\cup\mathcal{K}_t\) | 父线；\(p_k=0\) 表示根 |

活跃集（只有活跃线参与接纳新稿）：

\[
A(t) = \{k \in \mathcal{K}_{t-1} : t - t_k^{\ell} \le \delta\}
\]

休眠阈 \(\delta\) 为待估参数（建议网格 \(\{3,7,14\}\) 日）。

### 1.4 日更新接规则（结构的全部来源）

对 \(d \in \mathcal{D}_t\)，令

\[
k^{\star}(d) = \arg\max_{k \in A(t)} \hat\phi(d)^{\top} \mu_k,\quad
\sigma(d) = \hat\phi(d)^{\top} \mu_{k^{\star}}
\]

\[
\mathrm{assign}(d) =
\begin{cases}
k^{\star}(d) & \sigma(d) \ge \theta_{\mathrm{in}} \\
\text{新建根线} & \sigma(d) < \theta_{\mathrm{in}}
\end{cases}
\]

归入后更新 \(\mu_k,\ t_k^{\ell},\ C_k\)。**已归入的历史稿不重新分配**（过去冻结）。这是可验证性的前提：同一语料按时间重放必须得到同一 \(\{C_k\}\)。

### 1.5 分裂（衍生的唯一定义）

当 \(|C_k| \ge n_{\mathrm{chk}}\) 且本线在当日有新稿时，对 \(C_k\) 做一次球面 2-means，得到子集 \(C^{(1)}, C^{(2)}\) 与中心 \(\mu^{(1)},\mu^{(2)}\)。若同时满足

\[
|C^{(j)}| \ge n_{\min},\quad
\mu^{(1)\top}\mu^{(2)} < \theta_{\mathrm{sp}},\quad
\min_j |\{d\in C^{(j)}:\tau(d)=t\}| \ge 1
\]

则把较小的新侧立为子线 \(k'\)，\(p_{k'} = k\)，并从 \(C_k\) 中移出 \(C^{(k')}\)（或复制指针、根线保留全部历史——实现选一种并写死；评测要求两种都报告，默认**根保留全部、子只含分出侧**，避免质量守恒被破坏）。

未满足分裂条件的相近稿不是衍生，只是同一线的后续。

### 1.6 查询窗上的四个量

给定闭区间 \(W=[t_a,t_b]\)。

**质量与突发**

\[
m_k(W) = |\{d\in C_k:\tau(d)\in W\}|
\]

\[
z_k(W) = \frac{\bar n_k(t_b-2:t_b) - \mathrm{mean}(n_k(t_b-9:t_b-3))}
{\mathrm{std}(n_k(t_b-9:t_b-3))+\varepsilon}
\]

其中 \(n_k(t)=|\{d\in C_k:\tau(d)=t\}|\)。无历史则 \(z_k=0\)。

**核心议题**（根线里截断，不预置「有几个主题」）

\[
\mathrm{score}_k(W) = \lambda \frac{m_k(W)}{\max_{j} m_j(W)} + (1-\lambda)\, \mathrm{clip}(z_k(W),0,z_{\max})
\]

\[
\mathrm{Core}(W) = \{k : p_k=0,\ m_k(W)\ge m_{\min},\ t_k^{\ell} \ge t_b-\delta,\ \mathrm{score}_k \ge \rho \max_j \mathrm{score}_j \}
\]

\(\rho \in (0,1)\) 用调参折自动选，测试集冻结。输出按 score 降序。

**衍生议题**

\[
\mathrm{Der}(W) = \{k : p_k \in \mathrm{Core}(W),\ m_k(W) \ge m_{\min}^{\mathrm{ch}} \}
\]

每条必须带 \(p_k\)。不能指回核心的簇不得标成衍生。

**迁移路径**  
将 \(W\) 按步长 \(\Delta\) 切成相邻列 \(W_1,\ldots,W_L\)（测试默认 \(\Delta=7\) 日、列可重叠 0 或 3 日，两种都跑）。列 \(i\) 的活跃线 \(U_i=\{k:m_k(W_i)\ge m_{\min}\}\)。匹配

\[
S_{uv} = \hat\mu_u^{(i)\top} \hat\mu_v^{(i+1)}
\]

边集 \(E_i = \{(u,v): S_{uv}\ge \theta_{m}\}\)，允许多对多。算子由度数定义，与生成无关：

| 条件 | 算子 |
|------|------|
| \(u\) 无出边 | decay |
| \(v\) 无入边 | emerge |
| 恰好 1-1 且 \(S_{uv}\ge \theta_{m}\) 且 \(\mathrm{sim}(\mu_u,\mu_v)\ge \theta_{\mathrm{sh}}\) | continue |
| 恰好 1-1 但 \(\mathrm{sim}(\mu_u,\mu_v)< \theta_{\mathrm{sh}}\) | shift |
| 1 出多 | split |
| 多入 1 | merge |

\(\theta_{\mathrm{sh}} > \theta_{m}\)。shift 表示中心已漂、身份仍匹配（报道焦点迁移）。

**生命周期**  
序列 \(\{n_k(t)\}_{t=t_k^{0}}^{t_b}\)。3 日滑动均值 \(\tilde n_k\)。阶段为分段函数（阈值进网格，测试冻结）：

- emerge：\(\tilde n\) 从 0 变为连续 ≥2 日正
- grow：近 3 日斜率 \(> \eta\)
- persist：高强度且斜率绝对值 \(<\eta\)
- decay：斜率 \(< -\eta\)
- dormant：曾活跃后连续 \(\delta\) 日为 0

as_of \(t_b\) 的阶段 = 该日所属段。禁止用模型标注阶段。

## 2. 技术选型

| 模块 | 选择 | 不选 |
|------|------|------|
| 编码器 \(\phi\) | 本地 `BAAI/bge-small-zh-v1.5`（或同系列 `bge-m3`，调参期二选一后冻结） | 在线 API 嵌入（不可复现）；LLM 隐空间 |
| 归入 | 单遍最近中心 + \(\theta_{\mathrm{in}}\) | LDA / 固定 \(K\)；每片独立 BERTopic（无稳定 id） |
| 衍生 | 条件球面 2-means 分裂 | LLM 判断「是否子题」 |
| 核心排序 | \(m_k,z_k\) 线性分 | LLM 投票谁是核心 |
| 匹配 | 中心余弦 + 多对多阈值 | 1-1 匈牙利（会抹掉 split） |
| 名称 | 仅对 \(\mathrm{Core}\cup\mathrm{Der}\) 事后起名 | 名称不当 id |

日更复杂度：活跃线数量 \(K_A\)，每天 \(O(|\mathcal{D}_t|\cdot K_A \cdot m)\)。环球网 \(K_A\) 预期几十量级，单机足够。

**参数（只在调参段估计，测试段一次冻结）**

\(\theta_{\mathrm{in}},\ \theta_{\mathrm{sp}},\ \theta_{m},\ \theta_{\mathrm{sh}},\ \delta,\ n_{\mathrm{chk}},\ n_{\min},\ \lambda,\ \rho,\ \Delta\)

网格先粗后细。调参目标见 §4，**不得**用测试段人工标注去挑 \(\theta\)。

## 2.1 数据流转

三层对象：**文档 ⊂ 故事 ⊂ 主题**。写路径只产生文档向量和故事线；主题与四个视图是查询时的只读派生。河流图只消费主题层。

```text
                    ┌─ 只读 ─────────────────────────────────────────┐
jsonl 日更稿         │                                                │
(doc_id,title,      │                                                │
 body,publish_time) │                                                ▼
        │           │                                         人工金标 / M0–M4
        │只读        │                                         （不回写线库）
        ▼           │
┌───────────────┐   │
│ 嵌入缓存 L0   │───┤  共用，算过不重算
│ doc_id → φ̂   │   │
└───────┬───────┘   │
        │当天新向量  │
        ▼           │
┌───────────────┐   │
│ 日更构建      │   │  只分配当天稿；历史成员冻结
│ 并入 / 开线 / │   │
│ 条件分裂      │   │
└───────┬───────┘   │
        │只增        │
        ▼           │
┌───────────────┐   │
│ 故事线库 L1   │◄──┘

└───────┬───────┘

        ▼

│ 查询派生 L2   │     │ 可选 LLM 起名     │

│ 迁移边        │
│ 日强度        │
└───────┬───────┘
        │
        ├─► 河流图     只吃 L2 核心（+「其他」）的 n_theme(t)
        ├─► 冲积/桑基  L2 列间匹配；或 L1 的 TOP-K
        ├─► 泳道/点    L1 故事 × 见报日
        └─► 树         点开一个 theme 看下属故事与子线
```

**各层写什么、谁读**

| 层 | 写入时机 | 写入内容 | 谁读 | 禁止 |
|----|----------|----------|------|------|
| 文档 jsonl | 爬虫已完成 | 原文 | 嵌入、评测点回 | 主题模块改稿 |
| 向量缓存 | 新 `doc_id` 首次出现 | \(\hat\phi\) | 构建、对照实验 | 用 LLM 当 \(\phi\) |
| 故事线库 | 每个见报日结束 | 新成员行、新故事、偶发 `parent_id` | 查询、评测 BCubed | 改昨天的归属 |
| 主题与四视图 | 查询时现算（可缓存 `(W,参数哈希)`） | `theme_id` 及其成员 `story_id`、Core/Der、边、`n(t)` | 前端 / 河流图 | 把主题写回故事库当事实 |
| 展示名 | 查询后可选 | 字符串 | UI | 当主键、进指标 |
| 金标 | 人工 | `doc_id → gold_story`（及可选 `gold_theme`） | 只进评测报告 | 调 \(\theta\)、写线库 |

**日更一条稿的落点**

1. 读 jsonl → 命中或写入向量缓存。  
2. 与活跃故事中心比：并入或新根。  
3. 必要时分裂 → 多一条子故事、写下父指针。  
4. 停。**此时还没有主题。**

**一次窗口查询的落点**

1. 取出 \(W\) 内 \(m_k>0\) 的故事（及仍活跃的根）。  
2. 对故事中心再聚类得到主题（L2，条数随数据，河流图只用其中 Core，大约 5～8）。  
3. 核心 = 主题层截断；衍生 = 核心下的故事或子故事；迁移 = 主题（或 TOP 故事）列间匹配；寿命 = 主题为故事日稿之和、故事为自身 \(n_k(t)\)。  
4. 河流图只订阅 L2 的日/周序列；不订阅 L1 全量。

**缓存键**

- 向量：`doc_id`。  
- 故事：全局 `story_id`，跨查询稳定。  
- 主题：`hash(W, Δ, 故事中心版本, θ_theme)`。换窗可以换 `theme_id`；不要假装和故事 id 一样稳。若产品要「河的颜色跨周不变」，应对主题做相邻窗匹配，把稳定色号写在查询缓存里，仍不要写进故事库。

## 3. LLM：用不用、用在哪

**结构路径不用 LLM。** 归入、分裂、核心分数、匹配算子、生命周期阶段全部由 §1 的式子确定。否则无法「同一 jsonl + 同一参数 → 同一结果」，也无法谈验证。

| 用途 | 是否用 | 怎样用 | 是否进入指标 |
|------|--------|--------|----------------|
| 嵌入 / 聚类 / 排序 / 匹配 | 否 | — | — |
| 给 \(\mathrm{Core}\cup\mathrm{Der}\) 起 8～16 字名称 | 是 | 只输入该线窗内标题列表（最多 15 条）+「专名优先，禁止推测未出现的意图」 | 否。评测用 \(k\) 不看名称 |
| 辅助人工预标「是否同一报道线」 | 可选 | 成对标题判定 yes/no，**必须**再由人抽查；不能当金标 | 否，除非双人与模型 IAA 另报 |
| 写简报 | 本测试不做 | — | — |

若用现有 MaaS：仅起名，温度 0，固定模型名与 prompt 哈希写入运行记录。名称失败不影响 \(C_k\)。

## 3.1 可视化：气泡图、演化时间线、主题河流图

三张图消费**同一份查询结果** `ThemeSlice(W)`，禁止各画各的聚类。分工按层次：

| 图 | 回答什么 | 吃哪一层 | 粒度 |
|----|----------|----------|------|
| 主题气泡图 | as_of \(t_b\) 有哪些核心、谁大、谁在爆发、衍生挂在谁下面 | L2 核心 + 其下 L1 | **截面**，不画整段历史 |
| 演化时间线 | 这些主题/故事上，稿件落在哪几天 | 默认 L2 行；点开一行下钻 L1 点（文档） | 中：行少、点细 |
| 主题河流图 | 核心主题体量如何涨落 | **只** L2 核心（+「其他」）的 \(n(t)\) | **最粗**，5～8 条带 |

衍生和迁移不要塞进河。衍生给气泡（父子包含）；迁移给时间线上的算子标记，或另开冲积图（本次三件套不强制）。

### 共用载荷

一次查询只产出一份 JSON，三图只做投影：

```text
ThemeSlice(W):
  themes[]   theme_id, parent_theme=0, mass, z, stage, color_key,
             daily[{day, n}], story_ids[], name?
  stories[]  story_id, parent_story, theme_id, mass, daily[], doc_ids[]
  docs[]     doc_id, day, title, story_id, theme_id
  other.daily[]    未进 Core 的稿量（给河的「其他」带）
  migration[]      from_id, to_id, day, op   （时间线标记用）
```

守恒（可视化验收，可用程序查）：

- 任意日 \(t\)：\(\sum_{\mathrm{Core}} n_{\mathrm{theme}}(t) + n_{\mathrm{other}}(t) = |\mathcal{D}_t \cap W\text{当日}|\)（河宽之和 = 当天稿数）。
- 气泡面积所用 `mass` 与时间线上该 `theme_id` 的点数相同。
- 点必须能回 `doc_id`。

颜色：`color_key` 来自相邻窗主题匹配，写在查询缓存，不写故事库。三图共用同一套色。

### 主题气泡图

**推荐形态：as_of 圆填充（circle packing），不要用 UMAP 当第一版。**

- 大圆 = Core 主题，半径 \(\propto \sqrt{m_k(W)}\)（面积正比稿量）。
- 大圆内小圆 = 该主题下质量最高的若干故事（衍生/主线），半径 \(\propto \sqrt{m_{\mathrm{story}}}\)。
- 填色 = 生命周期阶段或 \(z_k\)（突发），图例写死：生长 / 平台 / 衰退 / 休眠。
- 布局用包含关系，不靠随机投影，同一 `ThemeSlice` 重绘位置稳定（可对 theme_id 排序后确定性打包）。

不推荐第一版做语义气泡云（t-SNE/UMAP）：位置不可复现，也无法在环球网金标上验收。若以后要「相近主题靠近」，用主题中心余弦做力导向，同样固定种子。

交互：点大圆 → 三图同时过滤该 `theme_id`；点小圆 → 时间线只保留该故事的点。

### 演化时间线

**推荐形态：泳道。横轴日历，纵轴默认 Core 主题（条数 = 气泡大圆个数）。**

- 行背景条：该主题从窗内首篇到末篇的存活区间。
- 点：`docs[]` 按 `day` 落在所属 `theme_id` 行；点半径可恒定（环球网一天才十来篇，不必再按量缩放）。
- 行尾或行内标记 `migration[]`：split / merge / emerge / decay 用小符号，**不要**把线画到另一行（那是冲积图的职责，叠在泳道上会糊）。
- 下钻：点行名 → 该行拆成下属 `stories[]` 子泳道，点仍是文档。这就是 Nexus 那张图的粒度，只在下钻后出现，总览保持和河、气泡同层。

纵轴不要默认铺开全部故事：窗内 L1 可达十几到几十行，和河流图的粗粒度冲突。

### 主题河流图

**推荐形态：堆叠流图（ThemeRiver），不是 TextFlow 分叉河。**

- 每条带 = 一个 Core `theme_id`，带宽 = 3～7 日滑动后的 \(n_{\mathrm{theme}}(t)\)（环球网按日会锯齿，默认 7 日平滑，调参段比较 3/7）。
- 最外一条「其他」= `other.daily`，避免河宽不等于当天稿数。
- 带数上限 = \(|\mathrm{Core}|\)，约 5～8；超了先并进「其他」，不要把衍生故事提成带。
- 不画 split 叉：分叉交给时间线符号。河只表达寿命与体量。

实现可选 ECharts `type: 'themeRiver'`（或同构的 d3-streamgraph）。输入即 `themes[].daily` + `other.daily`。平滑在服务端算好再下发，前端不改计数。

### 三图联动（同一 W）

```text
选定 W（可在河上刷一段 → 重算 ThemeSlice）
    ├─ 气泡：t_b 截面
    ├─ 河：整段 W 的 L2 体量
    └─ 时间线：整段 W 的点
选中 theme_id
    ├─ 气泡：其余淡化
    ├─ 河：其余带降低不透明度
    └─ 时间线：可下钻该主题的故事
```

刷窗等于改 W，必须重跑 L2 聚类（主题 id 可能变）。选中不等于重聚类。

### 和四个产品问题的对应

| 产品问题 | 主图 | 辅图 |
|----------|------|------|
| 当前核心 | 气泡（大圆） | 河在 \(t_b\) 最宽的几条带 |
| 衍生 | 气泡内小圆 | 时间线下钻后的子泳道 |
| 议题迁移 | 时间线上的算子标记 | 非本三件套的冲积图 |
| 生命周期 | 河的带宽变化 | 气泡颜色 = as_of 阶段 |

LLM 名称只填 `name` 字段，三图图例共用；缺名则显示 `theme_id` 前缀。名称错误不改几何。

## 4. 在环球网语料上如何验证

### 4.1 时间切分（先写死）

| 段 | 日期 | 篇数 | 用途 |
|----|------|------|------|
| 调参 | 2026-03-29～08-31 | 2228 | 网格选 \(\theta\)，只看程序指标与少量自检 |
| 冻结测试 | 2026-09-01～10-02 | 328（32 日） | 参数只读，报告一次 |
| 人工金标窗 | 2026-09-19～10-02 | 137 | 报道线标注，算 BCubed 等 |

系统按时间顺序吃完全部调参段，再继续吃测试段（模拟日更）。禁止打乱、禁止用未来稿更新过去中心（指数加权只含 \(\tau\le t\)）。

### 4.2 不依赖人工的程序指标（调参用）

在调参段按日回放，记录：

1. **单篇率** \(r_{\mathrm{sg}} = |\{k:|C_k|=1\}|/K_t\)。过高说明 \(\theta_{\mathrm{in}}\) 太大。
2. **活跃线数** \(|A(t)|\) 的日中位数。环球网日更约 13 篇，中位活跃线预期大致 8～25；超出则阈值失当（经验带，不是金标）。
3. **时间紧致性**：对 \(|C_k|\ge 4\) 的线，成员见报日的四分位距 IQR。过大说明把相隔很久的不同事态并在一起。
4. **回放确定性**：同一代码跑两遍，成员划分的哈希一致。
5. **冻结性**：日 \(t\) 结束时的 \(C_k\cap\mathcal{D}_{\le t-1}\) 与昨日完全相同。

调参选 \(\theta\)：在 \(r_{\mathrm{sg}}\in[0.15,0.45]\) 且 IQR 中位不超过 10 日的前提下，最大化「非单篇线的平均规模」。这是启发式，测试段不得再改。

### 4.3 人工金标（测试段，验证用）

对象：金标窗 137 篇的 `(doc_id, title, publish_time)`，**不看模型输出**。

标注员把稿划入开集「报道线」（同一正在发展的事态；评论/背景综述单独标 `singleton` 或 `background`）。允许一条线跨多日。标注「父线」仅当明确是从某线分出的新焦点（例如同一地区冲突下新开的护航线）；吃不准则不标衍生，宁可漏。

指标（测试段只报这些）：

| 问题 | 指标 | 通过线（初值，可在看数前改，看数后不许改） |
|------|------|------------------------------------------|
| 片内聚得对不对 | 相对人工线的 BCubed P / R / F | F ≥ 0.60 为可运行；≥ 0.75 为可用 |
| 核心 | 人工「窗内最主要的 3 条线」与 \(\mathrm{Core}\) 的 IDF 集合 Jaccard | ≥ 0.40（3 条对 TOP 自动截断，本来就松） |
| 衍生 | 人工父→子边的召回；系统多出来的子边作精确率 | 先报数，样本小不设硬线，但每条假阳性要能点回标题 |
| 迁移 | 对相邻两周，人工 2×2：延续/新生/消亡/分叉 与系统算子一致率 | ≥ 0.70（只评 Core 涉及的线） |
| 生命周期 | 人工对每条金标线标一个 as_of 末日阶段（生长/平台/衰退/休眠） vs 系统阶段 | 一致率 ≥ 0.60 |
| 名称（若启用 LLM） | 人工：名称是否可由标题推出、有无编造专名 | 编造率 = 0 |

点回：每条系统线输出成员 `doc_id` + 标题，评测可审计。

### 4.4 对照实验（证明选型不是空话）

同一金标、同一切分，必须跑完：

| 编号 | 系统 |
|------|------|
| M0 | 每篇独自一条线（下界） |
| M1 | 本方案（单遍 + 分裂） |
| M2 | 本方案但 \(\theta_{\mathrm{sp}}=0\)（禁止分裂）→ 衍生应变差 |
| M3 | 按周独立聚类（HDBSCAN 或凝聚）+ 中心对齐，历史可重分配 |
| M4 | 固定 \(K=10\) 的日切片 LDA + 词分布余弦对齐 |

预期：M1 的 BCubed F 高于 M0、M4；M1 衍生召回高于 M2；M3 的 id 稳定性（相邻日成员 Jaccard）低于 M1。若 M3 全面优于 M1，则改结论为「该语料更适合切片重聚」，而不是调 prompt。

## 5. 交付与复现

运行记录必须包含：嵌入模型名与维度、全部冻结 \(\theta\)、语料文件哈希、随机种子（2-means）、代码版本。输出每条线：

```text
topic_id, parent_id, first_day, last_day, member_doc_ids[], daily_counts[],
score_W, role ∈ {core, derived, other}, operator_edges[]
```

名称字段可空。缺成员 id 的结果视为不可评。

建议实现顺序（均在调参段上）：（1）嵌入缓存；（2）无分裂的单遍归入 + 程序指标；（3）加分裂；（4）窗查询四视图；（5）金标窗人工 + M0–M4；（6）可选起名。

## 6. 本方案明确不覆盖

- 发生日 / 背景句过滤（无抽取则做不到）
- 跨源合并（测试只有环球网军事一源）
- 用 LLM 发现主题或判定核心
- 把栏目「军事」当作议题闭集
- 因果（「导致」）——匹配算子只描述报道线分合与中心漂移
