# 论元体系重构说明（去通用层 + 按类型细化）

## 一、为什么改

上一版保留了「施事/受事/涉及」三个通用角色，对所有事件类型开放。实测暴露出三类问题：

1. **重复填充。** 同一事件里施事与专属角色并存 25 次，其中 15 次值完全相同：
   ```
   合作·签署   施事=泰国第一军区   甲方=泰国第一军区
   表态·声明   施事=伊朗武装部队哈塔姆安比亚中央总部   表态方=同一串
   治理·行政   施事=内务部         主体=内务部
   ```
2. **口径不一致。** 注释写「通用角色（施事、涉及）」，校验代码硬编码 `("施事","涉及","包含","到场")`，少了「受事」。标注端按 `TYPE_SLOTS` 建下拉框，漏掉通用角色，导致「施事」被浏览器静默显示成第一项「受事」——即上一轮修的显示 bug。
3. **语义不统一。** 「涉及」在合作类装协议、对抗类装停火协议、表态类装报告，同一个槽位承担三种含义。

## 二、改成了什么

**取消通用层。每个二级类型声明一套封闭论元，施动角色按类型起专名。**

| 类型 | 论元（* 必填） |
| --- | --- |

| 对抗·拦截 | 拦截方*、拦截对象*、袭击方、发射平台、发射物、战果 |
| 对抗·发射 | 发射方*、发射平台、发射物*、打击对象 |
| 对抗·控制 | 控制方*、受控方、控制对象 |
| 部署·投送 / 机动 | 部署方*、兵力*、起点、终点* |
| 部署·战备 | 部署方*、兵力、终点 |
| 部署·演习 | 部署方*、兵力、起点、终点 |
| 部署·撤离 | 部署方*、兵力*、起点*、终点 |

共 27 个二级类型、44 个槽位名（去重）。

## 三、单一事实源

新增 `extract/slots.py`，是本体的唯一来源：

```python
SLOTS     = {"对抗": {"打击": [Slot(...), ...], ...}, ...}
DOMAIN    = _build_domain()      # 槽位名 -> [(头类型, 尾类型), ...]，支持同名多义
ROLE_NAMES                       # 全部论元名
LITERAL_SLOTS                    # 含字面值的槽位
ACTOR_SLOTS                      # 施动方类槽位，记者/发言人不能当
prompt_block()                   # 生成提示词里的槽位表
slot_names(event_type, subtype)  # 某类型允许的槽位名
```

四处消费方都改成从这里取，不再各写一份：

| 位置 | 原状态 | 现状态 |
| --- | --- | --- |
| `extract/kg_extract.py` 提示词 | 手写 28 行静态文本 | `{slot_table}` 占位，由 `prompt_block()` 生成 |
| `extract/kg_extract.py` 校验 | `TYPE_SLOTS` + 通用角色硬编码例外 | `slot_names()` 严格封闭校验 |
| `annotate/tasks.py` schema | 手写 `SLOTS_BY_SUBTYPE` | 由 `slots_of()` 派生 |
| `dataset/build.py` 切分 | 手写 `EE_RELATIONS` 集合 | 由 `ROLE_NAMES` 派生 |

中英文提示词共用同一张表。英文稿的槽位名保持中文，因为槽位名是数据字段，不翻译。

## 四、同名多义的处理

「部署方」有两义：

- 作**事件论元**：事件 → 机构（谁执行的部署）
- 作**实体关系**：装备 → 机构（装备由谁部署）

`DOMAIN` 改为 `{name: [(head_types, tail_types), ...]}`，校验时按头端点类型择一支：

```python
picked = None
for want_head, want_tail in DOMAIN[name]:
    if types_of[head] & want_head:
        picked = (want_head, want_tail)
        break
```

`dataset/build.py` 切分卷时也按「头端点是不是事件」判别，避免把事件的部署方论元漏进 RE 卷。

## 五、顺带修的两个 bug

**1. 关系校验的 KeyError（会导致整篇抽取失败）**

`check_block` 里先用 `types_of[head]` 做多义择支，但对 head 的存在性检查写在这之后。模型给出一个不在保留事件/实体表里的 head 时（如「俄军」被事件长度校验丢弃），直接抛 `KeyError`，整篇抽取失败。

该异常被 `extract_doc` 的 `except` 吞掉，只记进 `errors`，表现为「这篇 0 个事件」。试抽时一篇「俄国防部称已大规模打击乌军工企业」因此变成空稿。

修法：把 head 存在性检查提到多义择支之前。

**2. 必填等级被模型过度解读**

试过给 `打击对象` 标条件必填（`~`），提示词写「原文点到才填，不要编造」，结果模型连施动方也不填了，零论元事件从 9 涨到 21。改为保持可选，但单独强调「施动方槽位必填」，并在 `prompt_block()` 里明确列出各类型的施动方槽位名。
