## 二、遗留问题

### 2.1 场景类型语义不正确

**问题**
场景定义为「事件所处的事态场面」，实际抽出的是动作短语。8432 个场景中 94% 是 8 字以内的动作词，按动作动词改判 3624 个为事件后，仍保留的 5550 个里含「活动」「开展工作」「声明」「答记者问」「例行记者会」「军事行动」这类非场面词，以及「12日战争」这类历史事件。

连带影响：「处于」边原 8428 条，其中 3589 条因终点改判为事件已改记为「涉及」，其余仍挂在语义不明确的短语上。

**原因**
提示只写了「场景是事件所处的事态场面」，没有可判定的判据，模型理解为「事件相关的动作」。事后规则只能在边缘修，改不了源头。

**解决方案**
1. 提示中给出场景的硬判据：必须由「地点性成分 + 状态」构成，例如「萨那城区巷战持续」「红海航道封锁状态」「边境地区高度戒备」；动词短语、活动名称、表态名称一律不收。
2. 提供 3 组正反例，正例覆盖战场态势、封锁状态、戒备状态，反例直接列出「遭到打击」「发动新攻势」「击落」「举行记者会」「发表声明」。
3. 抽取时要求场景同时给出所依附的事件，孤立场景不写。
4. 全量重跑后再看保留场景中合规比例，目标 ≥ 80%。

**代价**：4135 篇重抽，约 8 小时。

### 2.2 4 篇长稿输出被截断

**问题**
4119 篇中 4 篇连续三次触发 `finish_reason=length`，重试后仍失败，占 0.1%。全部是长篇综述：伊朗还击行动影响中东多国、真主党拒绝部分停火、中俄海上联合巡航、中国航展三十年。

**原因**
单块 3500 字符时长稿一次要输出上百实体、几百关系，超过 8000 token 输出上限。

**解决方案**
对超过 2500 字符的块采用分级策略：先按 3500 字符抽取，若返回截断则对同一块改用 1500 字符重切后重抽，合并结果去重。实现上在 `extract_one` 里按块处理，不改全局参数。预期这 4 篇可全部抽完。

**代价**：仅影响超长稿，整体耗时增加可忽略。

### 2.3 三跳与四跳路径仍为空

**问题**
登记的「事件 → 搭载装备 → 部署方机构 → 从属国家」与「事件 → 搭载装备 → 部署去向」两跳以上路径命中为 0。单跳覆盖良好：实施 10939、发表 8148、表明 4751、涉及 4825、搭载 1248。

**原因**
链条要求同一篇稿件内同时出现「事件动用某装备」「某机构部署该装备」「该机构从属某国」「该装备有部署去向」。全量 4115 篇里满足四环的稿件极少。部署边仅 147 条、去向 588 条，与事件节点几乎不重合。

**解决方案**
1. 短期：不把三跳以上作为能力承诺，路径能力按单跳扇出加两跳短链表述，与实测一致。
2. 中期：部署与去向这两类边改由专门的一次调用抽取，提示只聚焦「谁把什么装备部署到哪里、何时」，而不是混在通用提示里。分开抽能提高召回。
3. 长期：跨稿链只作线索视图，每级标明来源稿件，明确说明是拼接而非同稿事实。

### 2.4 事件切碎仍有残留

**问题**
去碎片化处理了结构过滤与子串合并（26605 → 24438），但同一句被切成两三个事件的情况仍存在。典型形态是「拦截并摧毁某导弹」与「某导弹」并列，或「残骸坠落引发火灾」与「引发火灾」并列。这些靠事后包含关系判断补不到，因为两条文本不构成子串。

**原因**
事件边界依赖模型对句法结构的判断，提示只能给原则，不能保证执行一致。

**解决方案**
1. 抽取后增加一步「同证据归并」：同一篇内 evidence 落在同一句的事件视为候选，交模型判断是同一事件的两次切分还是两件不同的事，只保留合并后的表述。
2. 该步只需对「同篇同句多个事件」的稿件调用模型。全量中这类稿件约占三分之一，成本远低于全量重抽。

### 2.5 英文 RSS 尚未纳入

**问题**
当前只跑了环球网军事 4115 篇。英文 RSS 已入库 17410 篇、8440 万字符，尚未抽取。

**成本**
按修复后的切块与实测吞吐，英文全量约需 500 小时（21 天），串行不可行。

**解决方案**
1. 先做并发改造：当前逐篇串行等请求返回，单篇约 7 秒。改为 8–16 路并发后需实测接口限流上限，预计可压缩到原来的 1/5 至 1/8。
2. 若并发受限，改为分层抽样：按媒体、篇幅、月份各取一定比例，例如每月 500 篇、合计 5000 篇，约 60 小时。抽样可覆盖各平台行文差异，够支撑验证。
3. 全量英文图谱作为后续批次，与中文图分开建库，人物与机构编号共用。

### 2.6 消歧未覆盖全部候选

**问题**
全量有 13718 个表面形式，类型内候选对远多于已判数量。当前只判了 500 对，合并 82 簇。大量同实体异写尚未合并，同一对象在图里仍是多个节点。

**解决方案**
1. 收紧候选生成：只在「规范化后相同」「共享已登记别名」「编辑距离 ≤ 2 且同类型」三种情形产对，去掉宽泛的包含匹配。
2. 按出现频次排序，高频实体优先判，低频长尾批量跳过（长尾多为一次性机构或地名）。
3. 判定结果写缓存，重复实体跨批次复用，避免全量重复调用。
4. 目标：高频命名实体（出现 ≥ 3 次者）全部判完，长尾按规则合并。

### 2.7 规范名覆盖率不足

**问题**
13718 个表面形式中，3189 个拿到中文维基条目对应的规范名，其余多为文中临时组合词（「也门政府卫生部门」「中国驻菲律宾使馆国防武官」），维基无对应条目。这些名称保持原文，没有统一的汉语规范形。

**解决方案**
1. 组合词按构词拆分规范化：「国名/机构名 + 部门名」拆成上级机构编号加职务属性，不强行造规范名。
2. 军衔、职务、部队番号建词表，按词表归一到已有节点。
3. 新增名称挂到已有类型之下，按词表次版本发布，与本体管理流程一致。

### 2.8 观点、立场、事件等句子型节点未汉化

**问题**
中文稿的句子型节点本身是汉语，无需处理。英文稿一旦纳入，观点、场景、立场、事件的节点名会是英文原句，图谱将中英混排。

**解决方案**
1. 专名层面：词表优先，其次中文维基标题，最后单条翻译，译文与英文原文成对保存并回写词表。
2. 句子层面：句子型节点增加 `display_zh` 字段保存汉语展示句，节点规范名仍用原文片段，边上摘录保持原文以支持偏移回指。查询与页面显示 `display_zh`，核对时打开摘录。
3. 不整篇翻译后再抽取，否则字符偏移对不回原文。

### 2.9 一致性检验模块未实现

**问题**
五项检验（结构、片段、话语、冲突、批次放行）在文档中已有定义，代码尚未实现。当前没有任何批次门禁，图产物直接可用。

**解决方案**
1. 结构：写入前用 LinkML 生成的 JSON 结构核对字段；入库后核对十类实体、关系名、两端类型、去向边终点是否为在册地点、摘录与原文编号是否齐备。
2. 片段：非空摘录、别名、人物属性按偏移回指为正文连续子串。
3. 话语：打击、部署、拦截、发射是否对应发生类；谴责、威胁、口头主张是否对应表态或计划。此项可直接复用抽取阶段的 `kind` 与线索校验逻辑。
4. 冲突：槽位不一致的主张双方是否均在且带冲突标记。
5. 四项待处理条数为 0 时批次放行，否则查询回落到上一批已通过数据。

## 三、优先级建议

| 优先级 | 问题 | 理由 |
| --- | --- | --- |
| 高 | 场景类型语义（一） | 影响十类之一的可用性，且必须在下次全量抽取前改好，否则要重跑两遍 |
| 高 | 长稿截断（二） | 改动小，可立刻消除 0.1% 的硬失败 |
| 高 | 一致性检验（九） | 没有门禁，后续所有结果都缺可验证性 |
| 中 | 事件切碎（四） | 影响事件数虚高与扇出质量 |
| 中 | 消歧覆盖（六） | 影响节点唯一性，进而影响路径 |
| 中 | 规范名覆盖（七） | 影响图谱可读性 |
| 低 | 三跳路径（三） | 可先按单跳能力交付，不作为承诺 |
| 低 | 英文纳入（五）、句子汉化（八） | 需英文抽取批次与并发改造，属下一阶段 |
